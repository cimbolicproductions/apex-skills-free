# SaaS Landing Page

## When to Use This Skill

- The user asks to write, roast, or improve a landing page.
- The user needs waitlist, pre-sell, fake-door, or Product Hunt launch page copy.
- The page has weak conversion, vague headline, or feature-first copy.

## When Not to Use This Skill

- The task is a long-form blog post or investor deck.
- The page is a non-conversion documentation site.

## Intake Questions

Ask only for missing information that changes the output. If enough context exists, proceed and state assumptions.

- Who is the ICP and what pain are they actively trying to solve?
- What is the one primary CTA?
- What proof exists: demos, screenshots, testimonials, numbers, pilots, or founder credibility?

## Operating Workflow

- Lead with transformation and pain relief, not features.
- Use a clear page order: hero, problem, outcome, how it works, proof, pricing or CTA, FAQ, final CTA.
- Remove navigation and secondary CTAs from dedicated conversion pages.
- Use you/your language and a concrete time, money, risk, or status outcome.
- Handle objections in FAQ: price, switching cost, trust, time-to-value, data/security, alternatives.
- If validation stage, make the CTA test a real commitment where possible.

## Output Contract

Always produce practical artifacts the user can copy, paste, configure, or hand to a contractor.

- Full section-by-section copy.
- Hero variants.
- CTA variants.
- FAQ objection handling.
- Conversion audit checklist.

## Quality Checklist

Before finalizing, verify:

- The hero explains what it is, who it is for, and why now in 5 seconds.
- There is only one primary CTA.
- Every feature is tied to a user benefit.
