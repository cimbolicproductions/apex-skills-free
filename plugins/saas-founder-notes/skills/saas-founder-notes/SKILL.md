# Founder Second Brain Notes

## When to Use This Skill

- The user wants to turn research, calls, or experiments into durable startup knowledge.
- The user uses Obsidian, Notion, Readwise, markdown, or second-brain workflows.
- The user needs product decisions linked back to evidence.

## When Not to Use This Skill

- The user only needs a short summary with no future retrieval use.
- The task is formal documentation for customers.

## Intake Questions

Ask only for missing information that changes the output. If enough context exists, proceed and state assumptions.

- What source material is being processed: call notes, transcript, article, video, research, or experiment?
- What product decision could this inform?
- Which system should receive the output: Obsidian, Notion, markdown files, or CRM?

## Operating Workflow

- Classify notes into Projects, Areas, Resources, or Archives.
- Extract exact quotes, pains, objections, alternatives, triggers, and product implications.
- Create permanent notes only for reusable insights, not every raw detail.
- Link each insight to a product hypothesis, roadmap item, ICP, or experiment.
- Run a weekly review that promotes raw notes into decisions and next actions.

## Output Contract

Always produce practical artifacts the user can copy, paste, configure, or hand to a contractor.

- Obsidian-ready markdown note.
- Wikilinks and tags.
- Evidence table.
- Product decision implications.
- Follow-up experiments.

## Quality Checklist

Before finalizing, verify:

- Insights are atomic and reusable.
- Raw observations are separated from interpretation.
- Every next action has an owner or trigger.
