# Reducer Tools

Use these tools when the user asks for reduction, ruthless editing, creative direction, product simplification, offer sharpening, or completion help.

## The Essence Extraction Pass

Purpose: identify what the work is actually about before changing it.

Steps:

1. Read or receive the whole work once without fixing.
2. Write a one-sentence “what this is really about.”
3. Write the intended feeling in one phrase.
4. Identify the one element carrying most of the power.
5. Identify everything that feels like explanation, justification, decoration, or fear.

Output:

```markdown
## Essence

This is really about:

## Intended feeling

The user should feel:

## Strongest element

## Noise

## First cut
```

## Reduce Past the Target

Rubin's reduction principle is not merely to cut to the desired length. Cut past it. Then add back what proves necessary.

Examples:

- If the user wants a 1,000-word essay, reduce to 500 words first.
- If the user wants a 10-slide deck, reduce to 5 slides first.
- If the user wants 7 features, reduce to 1 indispensable feature first.
- If the user wants 5 CTAs, reduce to 1 action.
- If the user wants a homepage, reduce to one screen.

Process:

1. Create the too-short version.
2. Ask what is genuinely missing.
3. Add back only the missing load-bearing pieces.
4. Refuse to add back comfort padding.

## The One-Instrument Test

Music analogy: if a song had only voice and guitar, would it still work?

Apply to any medium:

- Landing page: headline and CTA only.
- SaaS: one workflow only.
- Brand: one promise only.
- Sales offer: one pain and one outcome only.
- Essay: one claim only.
- Video: one scene or story only.
- Skill: one repeatable behavior only.

Ask:

> If this had to work with one instrument, what is the instrument?

Then build around that.

## The Decoration Audit

Cut or challenge anything that exists mainly to signal competence, taste, professionalism, or completeness.

Common decorations:

- Generic adjectives.
- Feature grids.
- “Trusted by” sections without proof.
- Abstract mission statements.
- Clever headlines that hide the promise.
- Extra brand colors.
- Long explanations before the point.
- Multiple CTAs.
- Complex onboarding before the magic moment.
- “AI-powered” language where the outcome matters more.
- Sections copied from competitors.

Reducer questions:

- Does this carry the center?
- Does this create the intended feeling?
- Is it here because the work needs it, or because similar works have it?
- Would removing it make the work scarier but stronger?

## The Fear Inventory

A surprising amount of creative clutter comes from fear.

Ask:

```markdown
What are you afraid someone will say if we remove this?
What are you afraid will happen if the simple version stands alone?
What part are you over-explaining because you do not trust the audience to feel it?
What part are you keeping because you worked hard on it?
What part are you making professional because the honest version feels exposed?
```

Then classify each element:

| Element | Fear it protects | Keep, cut, or test |
|---|---|---|

## The Hidden Poem Search

Purpose: find the material the user has dismissed.

Ask for:

- Scraps.
- Notes.
- Deleted lines.
- Old drafts.
- Voice memos.
- “Dumb” ideas.
- Too-personal stories.
- Unused demos.
- Offhand comments.
- The part they think is not relevant.

Look for:

- Emotional specificity.
- Unusual phrasing.
- Personal stakes.
- Clear tension.
- A detail that feels real.
- A rough line with more life than the polished version.

Output:

```markdown
## Hidden poem candidates

## Why they may matter

## Experiment
```

## Volume Before Selection

Do not over-invest in one version too early.

When the user wants quality but has too little material, prescribe volume:

- 10 headlines to get 1.
- 30 names to get 3.
- 5 product concepts to get 1.
- 3 landing page angles to choose a center.
- 20 video hooks to find the real one.
- 3 radically different UX flows before polishing one.

Volume rules:

- First drafts only.
- No defending.
- No explaining.
- No polishing until after selection.
- Select by aliveness, not correctness.

Selection table:

| Option | Lean-forward score | Truth score | Distinctiveness | Keep? |
|---|---:|---:|---:|---|

Use simple scoring only when it helps. Do not let scoring replace taste.

## Blind Testing

Use blind testing when labels, authorship, effort, or status contaminate judgment.

Applications:

- Compare headlines without knowing which one the user wrote first.
- Compare designs without knowing which took longer.
- Compare product ideas without revenue projections.
- Compare names without domain availability at first.
- Compare copy variants without strategy explanations.

Instructions:

1. Remove labels and backstory.
2. Present options anonymously.
3. Ask for immediate feeling.
4. Only then reveal context.

Prompt:

> I do not want the explanation yet. Give me the raw options unlabeled. I will react to what is there, not what it is supposed to be.

## Polarity Break

When the work is stuck in one habitual mode, make its opposite.

Examples:

- Dark → light.
- Serious → playful.
- Professional → raw.
- Long → tiny.
- Loud → quiet.
- Polished → demo.
- Complex → one-button.
- Premium → garage-built.
- Abstract → painfully specific.
- Safe → polarizing.

Prompt:

> What is the opposite version of this, and what does it reveal?

Use the opposite version not necessarily to ship, but to expose what the default version is hiding.

## Constraint Menu

Use constraints as creative technology:

### Writing

- One sentence only.
- No adjectives.
- No industry jargon.
- Must include one concrete image.
- Must be understandable by a 10-year-old.
- Must be written as a text message.
- Must begin with the uncomfortable truth.

### Product

- One user.
- One job.
- One screen.
- One button.
- One metric.
- One onboarding step.
- One magic moment in under 30 seconds.

### Landing Page

- No feature list.
- One promise.
- One proof.
- One CTA.
- Hero section only.
- No “AI-powered.”
- Must show before/after.

### Brand

- Two words.
- No category jargon.
- One enemy.
- One emotional territory.
- One sound or texture.
- Must be memorable when spoken aloud.

### Code / Automation

- One command.
- One input.
- One output.
- No configuration until necessary.
- Must run locally first.
- Must create visible value in one minute.

## Reversibility Check

More time does not always make work better.

Ask:

- Was an earlier version more alive?
- Did polish remove the original charge?
- Are we improving or sanding off identity?
- What did the rough version know that the polished version forgot?

If yes, restore the earlier energy and re-craft from there.

## Completion Gate

Use when the user asks “is this done?”

Decision:

- **Ship**: The center is clear, remaining changes are minor, and delay is likely fear.
- **Final pass**: One precise issue remains.
- **Sit**: The work needs distance, not more effort.
- **Cut**: The work is close but overbuilt.
- **Rebuild**: The center is wrong or absent.

Completion output:

```markdown
## Decision

Ship / final pass / sit / cut / rebuild

## Why

## One final move

## What not to touch
```

Always include “what not to touch.” Great work is often damaged in the last pass.
