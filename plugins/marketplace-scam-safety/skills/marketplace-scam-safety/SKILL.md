# Marketplace Scam and Safety Guard

## When to Use This Skill

- A buyer asks to move off platform, send verification codes, overpay, use unusual payment, or ship before payment.
- The user wants safe pickup, payment, or buyer screening rules.
- A message feels suspicious and needs triage.

## When Not to Use This Skill

- The buyer is normal and the user only needs negotiation wording.
- The transaction involves regulated goods requiring specialist legal/policy guidance.

## Intake Questions

Ask only for missing information that changes the output. If enough context exists, proceed and state assumptions.

- Paste the exact buyer/seller message.
- Platform, item value, payment method requested, pickup/shipping plan.
- What personal info has already been shared, if any?

## Operating Workflow

- Scan for red flags: verification codes, overpayment, fake payment emails, pressure, third-party pickup, suspicious links, off-platform move, cashier checks, gift cards, shipping before payment.
- For local sale, prefer in-person, daylight, public or safe-exchange location, and verified payment.
- Do not share codes, account info, exact home address unnecessarily, or personal documents.
- Check payment inside the actual payment app or platform, not from screenshots or emails.
- If suspicious, stop engagement and report through platform.

## Output Contract

Always produce practical artifacts the user can copy, paste, configure, or hand to a contractor.

- Risk rating: low, caution, likely scam.
- Red flags found.
- Safe reply or disengagement script.
- Meetup and payment checklist.
- Report/block instructions.

## Quality Checklist

Before finalizing, verify:

- Safety advice is conservative for high-value items.
- No recommendation relies on screenshots as proof of payment.
- The user is told when to walk away.
